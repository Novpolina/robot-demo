# Ответы на бонусные вопросы

Это схема переноса проекта на реального робота; физическое подключение в рамках симуляции не выполнялось. Конкретные напряжения, распиновку и драйвер нужно уточнять по модели купленных модулей.

## 1. Подключение к Raspberry Pi 5

**Orbbec Astra:** USB для питания и данных; при нехватке питания USB использовать питаемый USB-хаб. Перед выбором драйвера уточнить точную модель Astra и наличие Linux ARM64-сборки SDK. Старые Astra относятся к линейке OpenNI; Astra 2 и другие модели могут требовать иной SDK. Совместимость всей семьи с любым SDK предполагать нельзя. Официальные списки: [OpenNI SDK](https://www.orbbec.com/developers/openni-sdk/) и [Orbbec SDK](https://www.orbbec.com/developers/orbbec-sdk/).

**Ультразвуковой дальномер:** интерфейс зависит от модели. Для модуля с отдельными Trigger/Echo — цифровые GPIO, общее GND, измерение длительности импульса. Raspberry Pi использует логику 3.3 В. Если Echo выдаёт 5 В, нужен делитель или подходящий преобразователь уровня; напрямую подавать 5 В на вход GPIO нельзя. Для устойчивого измерения нескольких датчиков разумно использовать микроконтроллер и передавать дальности Pi по UART/USB. Датчики запускаются по очереди, чтобы уменьшить взаимные помехи. Модули I²C/UART подключаются через соответствующий интерфейс с согласованными уровнями.

**GPS:** USB-приёмник или UART TTL с уровнями 3.3 В. У UART соединяются TX приёмника → RX Pi и общий GND; RX приёмника нужен, если отправляются команды настройки. TTL-UART не следует путать с RS-232. Для работы GPS нужна антенна и нормальный приём спутников; интерфейс часто передаёт NMEA или протокол производителя. Точное питание определяется платой-модулем.

## 2. Питание от одного аккумулятора

Аккумулятор с подходящей защитой/BMS → предохранитель и выключатель → отдельные ветви питания:

- двигатели через драйвер и питание, рассчитанное на их рабочие и пусковые токи;
- стабилизированный DC/DC для Pi и USB-периферии;
- при необходимости отдельный DC/DC для датчиков, требующих других напряжений.

Для Pi 5 ориентир — качественный источник 5.1 В / 5 А с корректной реализацией USB-C-питания для этой платы. Источник должен выдерживать суммарную нагрузку Pi, камеры и остальных USB-устройств; одного значения «5 А» на неизвестной плате преобразователя недостаточно. Raspberry Pi документирует ограничение мощности USB-периферии при менее мощном источнике. [Официальные требования питания](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#power-supply).

Цифровые сигналы требуют общего опорного GND, а силовой ток моторов не должен идти по тонкому сигнальному проводу земли. Нужны развязка/фильтрация питания, конденсаторы у потребителей, подходящие провода и проверка падения напряжения при старте моторов. Лидар или камера не питаются от сигнальных GPIO.

Пример оценки времени работы: полезная энергия аккумулятора в Wh × КПД преобразователей / средняя мощность системы в W. При выборе компонентов учитывают максимальное напряжение полностью заряженного аккумулятора и пиковые токи, а не только номинальные значения.

## 3. Проверка датчиков без ROS

**Камера:** проверить появление USB-устройства (`lsusb`), затем открыть официальный viewer или standalone-пример подходящего SDK. Проверить получение RGB/depth-кадров, частоту и измерение расстояния до предмета на известной дистанции. Просмотр обычной RGB-картинки сам по себе не подтверждает работу depth-потока.

**GPS:** проверить последовательное устройство и открыть его через `gpsmon /dev/ttyUSB0` или подходящий порт UART. При работе через gpsd — `gpspipe -w`. Проверить поступление данных, статус фиксации, количество спутников и изменение координат при перемещении. NMEA-строки без valid fix ещё не означают, что позиция определена. [gpsmon](https://gpsd.io/gpsmon.html), [gpsd](https://gpsd.io/gpsd.html).

**Ультразвук:** standalone-программа на микроконтроллере либо GPIO-библиотека, совместимая именно с Pi 5; выдавать Trigger и измерять Echo с таймаутом. Преобразование длительности: `distance = speed_of_sound × echo_time / 2`. Проверить несколько известных дистанций, отсутствие отражателя и поведение при наклонной поверхности. Логический анализатор или осциллограф подтверждает наличие Trigger/Echo и помогает отличить ошибку подключения от программной задержки.

В каждом случае сначала проверяются питание и уровни, затем данные на физическом интерфейсе и только после этого — ROS-драйвер.
